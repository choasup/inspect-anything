# 02 · 自研模型架构设计（inspect-one：单骨干双头统一架构）

> 目标：在零售/安防/质检三个垂直场景上，效果超过通用开源 VLM 零样本水平，速度满足端侧实时（视频流 <100ms/帧）与产线节拍（单件 <200ms），且随飞轮持续拉开差距。
>
> 设计决策：**三个领域（含工业质检）全部用检测范式打底**，不引入独立的无监督异常检测模型；自研模型统一为**一个共享视觉骨干 + 两个解码头**，而不是两个独立模型。

## 1. 为什么不是单一解码器，也不是两个独立模型

先回答两个根本问题。

### 1.1 检测头与 VLM 头的本质区别：解码方式，不是任务

| | 检测解码头（det head） | LLM 解码头（vlm head） |
|---|---|---|
| 输出方式 | **一次前向并行输出**全部框/点 | **自回归逐 token 生成** |
| 单帧延迟 | 5-10ms | 100ms 起 |
| 输出容量 | 数百个目标无压力 | 框数受输出 token 上限制约，密集场景漏检 + 计数幻觉 |
| 词表 | 离线编译的 prompt 嵌入集（prompt-then-detect） | 自由文本即时理解 |
| 擅长 | 在哪里、有多少 | 是什么、为什么、合不合规 |
| 训练数据 | 框/点标注 | 指令、结构化对话、偏好对 |

货架 200+ SKU 逐帧检测、25fps 视频流，要求并行密集输出；陈列合规判定、缺陷归因、价签核对，要求语言推理。**这两种计算形态无法在一个自回归解码器里同时满足实时性**——Florence-2/DINO-X 证明了单一 seq2seq 接口可以统一任务，但自回归地"念"出几百个框的坐标，延迟随目标数线性增长，密集实时场景不可行。所以解码器必须是两个。

### 1.2 但编码器和训练管线必须是一个

之前"inspect-vlm + inspect-det 两个独立模型"的方案有三个实际代价：两套视觉表征语义不对齐（det 报的框,vlm 不一定认）、两套训练/数据管线、端侧两份显存。统一为单骨干后：

- 检测头直接消费 VLM 级语义的视觉特征（开放词汇泛化更强）；
- 飞轮的一份标注（框 + 结构化描述）同时喂两个头；
- 端侧只跑「骨干 + 检测头」时即逐帧实时；事件触发时复用**同一次编码的特征**走 LLM 头，无需重复编码图像。

## 2. inspect-one 架构

```
                    输入图像（原生动态分辨率，不切 tile）
                              │
              ┌───────────────▼────────────────┐
              │  共享视觉骨干                      │
              │  Phase1: PE core L + 多尺度adapter │
              │  Phase3: 自研混合层级（多教师蒸馏）   │
              └───┬───────────────────────┬────┘
        多尺度特征 P3/P4/P5          末层特征 → pixel unshuffle ×4
                  │                       │  (256-576 token)
        ┌─────────▼─────────┐   ┌─────────▼─────────┐
        │ 检测解码头 (~50M)   │   │ LLM 解码头         │
        │ DETR 式 query 解码  │   │ Qwen3-0.6B / 2.7B │
        │ 分类原型 = 离线编译  │   │ + 2 层 MLP 连接器   │
        │ 的文本 prompt 嵌入  │   │ 结构化输出约束解码    │
        └─────────┬─────────┘   └─────────┬─────────┘
            框/点/计数               比对/归因/审计/报告
            (5-10ms)               (事件触发, ~100ms)
```

关键设计：

| 组件 | 选型 | 理由（对应 01 文档结论编号） |
|------|------|------|
| 视觉骨干 | **Phase 1**：PE core L（0.3B，CLIP 式对比预训练）+ adapter 出多尺度特征；**Phase 3**：自研混合卷积-attention 层级骨干（FastViTHD 风格），从 PE（语义对齐）/ DINOv3（密集质量）/ SAM3（检测行为）多教师蒸馏 | 选型逻辑：**对齐难补、dense 可练**——文本对齐空间是开放词汇热更新的根基，事后补的成本高；dense 质量差距可被 SAM3 蒸馏的强监督部分抹平。DINOv3 ConvNeXt-S/B 作为检测分支对照实验，若细小缺陷召回优势显著则训练侧双骨干、蒸馏时合流 |
| 分辨率 | 原生动态分辨率，默认 1024 边长，质检模式 2048 | 长图不割裂（#1） |
| 检测头 | DETR 式 query 解码器，分类分支用文本 prompt 嵌入做原型（prompt-then-detect 范式），**含 presence head（识别与定位解耦，借鉴 SAM3）**，从 SAM3 蒸馏初始化 | 开放词汇 + 推理零文本编码开销（#8）；presence head 直接服务误报压制指标；规避 Ultralytics 许可 |
| 文本嵌入来源 | 复用 LLM 头的词嵌入空间（小投影层对齐） | 两个头共享同一语义空间，det 检出的类别与 vlm 的语言概念天然对齐 |
| 连接器 | pixel unshuffle ×4 + 2 层 MLP | 最简单最稳的 token 压缩（#4） |
| LLM | Qwen3-0.6B / 2.7B | 与教师同源词表，logits 蒸馏对齐成本最低 |
| 输出格式 | `<box>`/`<point>`/`<count>`/JSON 约束解码 | 结构化一等公民（#6） |

### 任务原语到解码头的路由

| 原语 | 走哪个头 | 说明 |
|------|---------|------|
| `ground(text) → boxes` | det 头 | 密集/实时；LLM 头也能输出框，仅用于教师蒸馏对齐和稀疏 grounding |
| `count(text) → int + points` | det 头 | 检测后计数，杜绝自回归计数幻觉 |
| `compare(region, ref) → diff` | vlm 头 | det 头先把 region 框出来 |
| `vqa(region, q) → answer` | vlm 头 | |
| `judge(image, rule) → pass/fail + evidence` | det → vlm 串联 | det 产 evidence 框，vlm 做规则判定 |

新场景接入 = 新 prompt 词表编译 + 新 rule prompt + 飞轮冷启动，不改架构。

## 3. 工业质检：统一到检测范式

不再使用无监督异常检测（PatchCore 路线）。缺陷即检测类别：`划痕 / 凹陷 / 异物 / 缺件 / 错装 …` 编译进检测头词表，与零售 SKU、安防目标完全同一套机制。

缺陷样本稀缺问题改由三个手段解决（详见 03 文档冷启动一节）：

1. **教师零样本伪标注**：Qwen3-VL 级教师 + Grounding DINO 对客户历史缺陷图打框，人审校正后成为种子集；
2. **缺陷合成扩增**：inpainting 方式把已知缺陷形态合成到正常件图像上（合成数据只进训练、不进评测）；
3. **开放词汇泛化**：检测头的文本原型分类天然支持新增缺陷类别热更新（重编译词表即可），长尾新缺陷由飞轮的新颖度采样持续回流。

代价要明说：纯检测路线对「从未见过、无法用语言描述」的未知缺陷形态，召回不如无监督建模。缓解：检测头保留一个通用 `defect/anomaly` 文本原型（教师用大量多样缺陷数据蒸馏），承担兜底召回角色；若某产线实测兜底召回不达标，再评估是否为该线单独加轻量异常分支——这是产品决策而非默认架构。

## 4. 训练配方（一套管线，三阶段）

复用 SmolVLM 开源 pipeline 骨架（**仅复用其训练管线与数据配方，不用其权重**——SmolVLM 无原生 grounding 训练目标，小档位效果也已被 Qwen3-VL 系反超），det/vlm 两头联合训练。

**蒸馏数据是离线数据资产，不是在线调用**：教师标注一次生成、版本化落盘，训练时只读数据集，不触碰教师服务；教师在线调用仅发生在飞轮的增量标注与仲裁环节。首轮训练 = 公开数据集 + 既有离线蒸馏数据，无需新的蒸馏产出。

1. **骨干+检测预训练**：Objects365/GoldG 等公开 grounding 数据 + SAM3 蒸馏（框/掩码/presence 信号），训 adapter 和 det 头（PE 骨干前期冻结、后期解冻微调）；LLM 不参与。
2. **多模态对齐 + 领域 SFT**：接上 LLM 头，先冻骨干训连接器，再联合微调。数据混合 = 30% 通用多模态指令（防遗忘）+ 50% 教师蒸馏领域标注 + 20% 人审金标；**det 头损失同步开启**（同一批图像的框标注），梯度按任务加权防止互相挤占。
3. **偏好优化（DPO/MPO）**：用飞轮人审改判天然形成的偏好对（#10），只训 LLM 头。

每轮飞轮迭代重跑阶段 2-3，周级节奏；阶段 1 仅在骨干升级时重跑。

## 5. 部署形态与速度预算

同一份权重，两种加载模式：

| 模式 | 加载 | 适用 | 延迟目标 |
|------|------|------|----------|
| 实时模式 | 骨干 + det 头 | 视频流逐帧、产线节拍 | Jetson Orin <10ms/帧（1B 档骨干） |
| 完整模式 | 骨干 + 双头 | 事件触发推理、巡检报告 | 1B@Orin <100ms；4B@边缘 GPU <150ms |

延迟预算的诚实说明：Phase 1 的 PE ViT 骨干在高分辨率下达不到混合层级架构的速度，靠**分辨率分级**（实时模式 640-896px、完整模式 1024px、质检模式 2048px 走云端/边缘 GPU）+ window attention + 量化过渡；<10ms/帧 的最终预算由 Phase 3 自研混合骨干达成。

事件触发链路：det 头逐帧跑 → 命中规则/告警 → **复用该帧已编码特征**送 LLM 头归因 → 结构化结果给规则引擎。VLM 调用量较逐帧降 ~100×。

其余速度手段不变：视觉 token 压缩至 256-576（prefill ↓4-9×）、结构化短输出（decode 步数 ↓5-10×）、W8A8 + 蒸馏后 QAT（吞吐 ↑2×，#12）、云端标注用投机解码（1B 给 4B 当 draft）。

## 6. 效果优势来源（不变）

1. **领域长尾**：通用模型没见过客户的 SKU 库和产线缺陷形态，飞轮回流是唯一来源；
2. **细粒度判别**：教师产「对比式」标注（为什么 A 不是 B），学生学判别性特征；
3. **误报压制**：安防/质检的核心指标是固定召回下的误报率，飞轮专门回流误报样本做 hard negative——通用模型做不了的客户级定制。
