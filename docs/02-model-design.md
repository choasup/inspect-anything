# 02 · 自研模型架构设计（inspect-vlm）

> 目标：在零售/安防/质检三个垂直场景上，效果超过通用开源 VLM 零样本水平，速度满足端侧实时（视频流 <100ms/帧）与产线节拍（单件 <200ms），且随飞轮持续拉开差距。

## 1. 总体形态：教师-学生双轨

```
                      云端（教师层）
  ┌──────────────────────────────────────────────┐
  │ Qwen3-VL-30B-A3B (自托管, FP8, vLLM)          │
  │   · 零样本兜底推理（新场景冷启动）              │
  │   · 飞轮自动标注 / 困难样本仲裁                 │
  │ Qwen3-VL-235B / 闭源旗舰（按需 API）           │
  │   · 标注质检抽样仲裁、评测集出题                │
  └────────────────┬─────────────────────────────┘
                   │ 蒸馏（伪标签 + logits + 偏好对）
                   ▼
                端/边（学生层）
  ┌──────────────────────────────────────────────┐
  │ inspect-vlm (1B / 4B 两档)                    │
  │   · 区域 VQA、归因、报告、价签/读表 OCR         │
  │ inspect-det (开放词汇实时检测头, <50M)         │
  │   · SKU/人/缺陷的密集检测、计数、跟踪输入        │
  │ inspect-ad (无监督异常检测, 仅质检线)           │
  │   · 正常样本建模, 毫秒级初筛                    │
  └──────────────────────────────────────────────┘
```

**为什么不是单一大模型打天下：** 货架上数百个 SKU 的密集检测、25fps 视频流逐帧分析，VLM 的自回归解码在物理上不可能满足延迟；反过来，纯检测模型无法做归因、比对、报告。三个组件各司其职，由同一个飞轮喂养。

## 2. inspect-vlm 架构细节

参数分配遵循「视觉重、语言轻」（InternVL3 的核心经验）：

| 组件 | 选型 | 理由 |
|------|------|------|
| 视觉编码器 | 混合层级架构（FastViTHD 风格）：前 3 stage 卷积下采样，后 2 stage attention；约 0.4B（1B 档）/ 0.9B（4B 档） | 高分辨率下编码延迟比纯 ViT 低 3-5 倍，token 数随分辨率增长缓（架构调研结论 #3） |
| 分辨率策略 | 原生动态分辨率，按长宽比缩放到 token 预算内（默认 1024 边长，质检模式 2048），不切 tile | 货架长图/产线宽幅图不被割裂（结论 #1） |
| 连接器 | pixel unshuffle ×4 + 2 层 MLP | 最简单、最稳、损失最小的压缩（结论 #4）；单图控制在 256-576 token |
| LLM | Qwen3-0.6B / 2.7B 底座 | 中英双语强、许可友好、与教师同源词表使 logits 蒸馏对齐成本最低 |
| 输出格式 | 结构化一等公民：`<box>`、`<point>`、`<count>`、JSON schema 约束解码 | 结论 #6；下游规则引擎直接消费，不做文本后处理 |

### 任务原语（统一三个领域的接口）

1. `ground(text) → boxes` — 开放词汇定位
2. `compare(region, reference) → diff` — 细粒度比对（陈列 vs 棚格图、工件 vs 标准件）
3. `count(text) → int + points` — 计数
4. `vqa(region, question) → answer` — 区域级问答/归因
5. `judge(image, rule) → pass/fail + evidence` — 规则审计（合规类任务的统一形态）

新场景的接入 = 写新的 rule prompt + 飞轮收集该场景数据，不改架构。

## 3. 速度优势的具体来源

| 手段 | 预期收益 | 说明 |
|------|----------|------|
| 混合层级视觉编码器 | 编码延迟 ↓3-5× | 对照纯 ViT-L 同精度 |
| 视觉 token 压缩至 256-576 | prefill ↓4-9× | TTFT 的主导项 |
| 结构化短输出 | decode 步数 ↓5-10× | 输出 JSON/坐标而非长文本 |
| W8A8 量化 + 蒸馏后 QAT | 吞吐 ↑2×，精度损失 <1pt | 发布流程标配（结论 #12） |
| 视频流：检测头逐帧 + VLM 事件触发 | VLM 调用量 ↓100× | 只有检测头报警/规则命中才唤醒 VLM |
| 投机解码（1B 给 4B 当 draft） | 云端批量标注吞吐 ↑1.5-2× | 飞轮标注成本优化 |

**延迟预算（4B 档，RTX 4000 级边缘 GPU，1024px 输入）：** 视觉编码 ~25ms + prefill ~40ms + 结构化解码 ~60ms ≈ **125ms**；1B 档在 Jetson Orin 上目标 **<100ms**。inspect-det 单帧 <10ms，覆盖视频流场景。

## 4. 效果优势的具体来源

通用模型在垂直场景的失分点，恰好是飞轮数据能补的：

1. **领域长尾**：通用模型没见过你客户的 SKU 库、你产线的缺陷形态。飞轮回流的真实分布数据是唯一来源。
2. **细粒度区分**：同品牌 330ml vs 500ml、划痕 vs 反光。蒸馏时让教师产「对比式」标注（为什么 A 不是 B），学生学到判别性特征。
3. **误报压制**：安防场景的效果指标本质是固定召回下的误报率。飞轮专门回流误报样本做 hard negative 训练，这是通用模型永远做不了的客户级定制。

### 训练配方（三阶段，复用 SmolVLM 开源 pipeline 骨架）

1. **对齐预训练**：冻结视觉塔与 LLM，只训连接器；通用图文对 + OCR 数据，约 50M 样本。
2. **领域 SFT**：全参数或 LoRA；混合 = 30% 通用多模态指令（防遗忘）+ 50% 教师蒸馏的领域结构化标注 + 20% 人审金标。结构化输出格式在此阶段固化。
3. **偏好优化（DPO/MPO）**：用飞轮里「教师仲裁 + 人审改判」天然形成的 chosen/rejected 对（结论 #10）。每轮飞轮迭代主要重跑阶段 2-3，周级节奏。

## 5. inspect-det 与 inspect-ad

- **inspect-det**：YOLO 系骨干 + 文本词表离线嵌入融合（prompt-then-detect 范式），从 Grounding DINO 蒸馏训练，规避 Ultralytics 商用许可。词表按客户场景离线编译，推理零文本编码开销。
- **inspect-ad**：PatchCore/EfficientAD 路线，每条产线用 100-500 张正常样本建库即可上线（冷启动无需缺陷标注）；检出异常裁剪后送 inspect-vlm 做归因（结论 #11），归因结果回流飞轮，逐步积累成有监督缺陷分类能力。
